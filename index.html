Auditoría y análisis de datos de ciberseguridad

1 1. Introducción

En este proyecto de la asignatura de Administración de Sistemas Informáticos en Red (ASIR), desarrollamos un informe técnico de ciberseguridad mediante el análisis de un conjunto de datos relacionado con ataques informáticos y actividad de red.

Utilizamos Python y las librerías Pandas, Matplotlib, Seaborn y Plotly. El informe se genera con Quarto, lo que permite combinar código, resultados, gráficos e interpretación técnica en una página web reproducible.

El objetivo es demostrar cómo un administrador de sistemas puede procesar datos de seguridad, estudiar incidentes, localizar patrones y obtener información que ayude a priorizar tareas de supervisión y protección.

2 2. Descripción del conjunto de datos

El conjunto de datos procede de Kaggle y se denomina Cyber Security Attacks, publicado por Incribo.

Es un conjunto de datos sintético que representa distintos escenarios de ciberseguridad. Por tanto, sus registros permiten practicar el análisis, pero no deben presentarse como mediciones reales de una empresa ni como una muestra representativa de todas las redes.

3 3. Carga e integración de los datos

En esta sección descargamos el conjunto de datos desde Kaggle y localizamos los archivos CSV disponibles. Comprobamos sus nombres antes de cargarlos para evitar seleccionar accidentalmente un archivo distinto del esperado.

Mostrar código 
import pandas as pd
import kagglehub
import glob
import os

# Descarga del dataset
path = kagglehub.dataset_download(
    "teamincribo/cyber-security-attacks"
)

# Localización de los archivos CSV
csv_files = sorted(
    glob.glob(os.path.join(path, "**", "*.csv"), recursive=True)
)

print("Archivos CSV encontrados:")
for archivo in csv_files:
    print(os.path.basename(archivo))

if not csv_files:
    raise FileNotFoundError("No se ha encontrado ningún archivo CSV")

# Identificamos los CSV que contienen las columnas principales esperadas.
columnas_requeridas = {
    "Timestamp", "Source IP Address", "Destination Port",
    "Attack Type", "Severity Level", "Action Taken",
    "Packet Length", "Anomaly Scores"
}

archivos_validos = []
for archivo in csv_files:
    muestra = pd.read_csv(archivo, nrows=5)
    if columnas_requeridas.issubset(set(muestra.columns)):
        archivos_validos.append(archivo)

if not archivos_validos:
    raise ValueError(
        "No se ha encontrado un CSV con las columnas esperadas. "
        "Revisa los archivos descargados y sus nombres de columnas."
    )

# Cargamos los archivos compatibles con el esquema esperado.
dataframes = [pd.read_csv(archivo) for archivo in archivos_validos]

if len(dataframes) > 1 and all(
    list(datos.columns) == list(dataframes[0].columns)
    for datos in dataframes
):
    df = pd.concat(dataframes, ignore_index=True)
    print(f"Se han concatenado {len(dataframes)} archivos CSV compatibles.")
else:
    df = dataframes[0].copy()
    print("Se ha cargado el primer CSV compatible con las columnas esperadas.")

print("Dimensiones iniciales:", df.shape)

3.1 3.1. Uso de concat() para reunir particiones

concat() permite unir DataFrames con una estructura compatible. Si Kaggle proporciona varios CSV con las mismas columnas, el bloque anterior los reúne. Si solo hay un CSV, dividimos temporalmente sus filas en dos particiones y las volvemos a reunir para demostrar el funcionamiento de concat() sin inventar una segunda fuente de datos.

Nota metodológica: esta segunda situación no equivale a integrar dos datasets independientes. Si se exige expresamente combinar dos fuentes distintas, habrá que incorporar un segundo conjunto de datos compatible y documentar su procedencia.

Mostrar código 
mitad = len(df) // 2
parte_1 = df.iloc[:mitad].copy()
parte_2 = df.iloc[mitad:].copy()

datos_unificados = pd.concat([parte_1, parte_2], ignore_index=True)

print("Filas de la primera partición:", len(parte_1))
print("Filas de la segunda partición:", len(parte_2))
print("Filas después de concat():", len(datos_unificados))

# Continuamos el análisis con el DataFrame unificado.
df = datos_unificados

Interpretación: el gráfico permite observar cómo se distribuyen los registros según el tamaño del paquete y la puntuación de anomalía. La interacción facilita aislar categorías y consultar detalles. Una posible relación visual debe investigarse con más datos antes de considerarla una regla de detección.

8 8. Interpretación desde la Administración de Sistemas

Los resultados permiten estudiar la distribución de los tipos de ataque, los niveles de severidad y las acciones defensivas registradas. Desde la perspectiva de un administrador de sistemas, este análisis puede servir como punto de partida para:

  • Revisar las políticas del cortafuegos y comprobar que se ajustan a los servicios que deben estar expuestos.
  • Investigar las categorías de eventos más frecuentes y verificar si corresponden a actividad esperada.
  • Priorizar la revisión de los registros clasificados con severidad alta.
  • Contrastar las acciones registradas (Blocked, Ignored o Logged, según los valores presentes) con las políticas de seguridad.
  • Establecer procedimientos de monitorización, conservación de logs y respuesta ante incidentes.
  • Investigar los eventos que presenten puntuaciones de anomalía elevadas junto con otras evidencias técnicas.

Limitación del análisis: el dataset es sintético y las asociaciones encontradas no demuestran causalidad ni describen necesariamente una red corporativa real. Las conclusiones deben entenderse dentro de los datos analizados.

9 9. Conclusiones

El proyecto demuestra cómo Python y Pandas permiten cargar, explorar, agrupar, filtrar y resumir información relacionada con la ciberseguridad. Las visualizaciones estáticas e interactivas ayudan a comunicar los resultados, mientras que la interpretación técnica conecta el análisis con tareas propias de la administración de sistemas.

Quarto integra el código, las tablas, los gráficos y las explicaciones en un informe reproducible.
